# Causal delivery of updates

Read an execution of the [Lamport clocks](../lamport-clocks/README.md) model, a finite list of events $e_0, \dots, e_{n-1}$ in which each event belongs to a process and may receive the message of the event at some position, as an execution of a replicated system whose replicas are the processes. An event that receives no message issues a new update, identified with the position of that event, and an event that receives from position $i$ delivers the update issued at position $i$. An update $u_1$ happened before an update $u_2$ when there is a chain of updates $u_1 = v_0, v_1, \dots, v_m = u_2$ with $m \ge 1$ in which each $v_l$ [directly precedes](directly-before.md) $v_{l+1}$: the replica that issues $v_{l+1}$ has issued or delivered $v_l$ before it issues $v_{l+1}$. So happened-before is the transitive closure of the replica-local order and of the order from delivering an update to issuing a later one. Shapiro et al. define happened-before between updates as direct precedence, without taking the transitive closure.

The execution provides *causal delivery* if every replica delivers an update $u_2$ only after it has delivered every update $u_1$ that happened before $u_2$, where a replica counts the updates it issues as delivered. That is, whenever the event at position $j$, of replica $r$, delivers the update $u_2$ issued at position $i_2$, and the update $u_1$ issued at position $i_1$ happened before $u_2$, some position $k < j$ holds an event of $r$ that either issues $u_1$ ($k = i_1$) or delivers it. This constrains only the order of deliveries within one finite execution: a replica may deliver an update more than once, or never, whereas the reliable causally-ordered broadcast that Shapiro et al. assume also delivers every update exactly once to every replica.

A receipt from a position that holds no issue delivers nothing and plays no part: it stands for a message that carries no update. The execution need not be [well formed](../lamport-clocks/well-formed.md): a receipt may name a later position, and a receipt that names a later issue delivers that update, both for causal delivery and for direct precedence.

When every receipt names an earlier issue, happened-before between updates is Lamport's [happened-before](../lamport-clocks/happens-before.md) between their issues ([Happened-before between updates, by delivery](happens-before-iff-trans-gen-delivered.md)). Otherwise the two relations can differ: a receipt from an earlier receipt delivers nothing, but adds a step to Lamport's relation.
