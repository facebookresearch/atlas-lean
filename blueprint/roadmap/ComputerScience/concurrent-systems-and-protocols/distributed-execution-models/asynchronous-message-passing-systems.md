# Asynchronous message-passing systems

In an asynchronous message-passing system, the processes $p_i$, for $i$ in a set $P$, are the nodes of a directed communication network $G$, which may have loops; the sources take $n$ processes, but nothing here needs $P$ to be finite. Process states range over a set $Q$ and messages over a set $M$. A *configuration* gives the state of every process and, for every ordered pair of processes, a channel $b_{ij}$: the multiset of messages sent from $p_i$ to $p_j$ but not yet delivered. A *protocol* gives each process a set of initial states and a deterministic transition function, which maps its state and a multiset of incoming messages, each paired with its sender, to a new state and a multiset of messages to send, each paired with its recipient, which must be an out-neighbour in $G$. Messages are thus sent only along the edges of the network, so a channel $b_{ij}$ with no edge from $p_i$ to $p_j$ stays empty in every execution. Pairing incoming messages with their senders follows Aspnes's delivery event $\mathrm{del}(i, A)$, which passes the transition function a multiset $A$ of (sender, message) pairs, although his transition function $\delta$ in Section 2.1.1 is typed on bare messages.

An *event* of $p_j$ delivers to $p_j$ a multiset $A$ of messages, each paired with its sender. It can occur in a configuration only if, for every $p_i$, the messages of $A$ from $p_i$ form a sub-multiset of $b_{ij}$. It removes them from these channels, gives $p_j$ the new state that its transition function assigns to its current state and $A$, and adds each message that the transition function sends to the channel from $p_j$ to its recipient. It is a *delivery event* if $A$ is nonempty and a *computation event* if $A$ is empty. A configuration is *initial* if every process is in one of its initial states and every channel is empty; the source leaves the initial configuration unspecified, and empty channels are the convention taken here. An *execution* is a [finite](is-execution.md) sequence $C_0, \varphi_1, C_1, \dots, \varphi_k, C_k$ or an infinite sequence $C_0, \varphi_1, C_1, \varphi_2, \dots$ of configurations and events in which $C_0$ is initial and each $\varphi_{l+1}$ can occur in $C_l$ and $C_{l+1}$ results from applying it.

There is no bound on message delay or on the relative speed of processes. An infinite execution is *admissible with lossy channels* if every process takes infinitely many computation events; a message that is sent may then never be delivered. With *reliable channels*, it is *admissible* if, moreover, every message sent is eventually delivered: whenever a message $m$ is in $b_{ij}$ in $C_l$, some event $\varphi_{l'+1}$ with $l' \ge l$ is an event of $p_j$ that delivers $m$ from $p_i$.
