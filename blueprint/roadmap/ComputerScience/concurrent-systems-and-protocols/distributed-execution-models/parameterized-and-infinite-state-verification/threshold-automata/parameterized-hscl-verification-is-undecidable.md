# Parameterized verification of round-based process templates against HSCL is undecidable

Asynchronous round-based distributed algorithms, modeled by a process template run by any admissible number of identical processes communicating by broadcast under threshold guards, cannot be verified algorithmically against specifications of the logic HSCL, which counts process visits to locations per round.

**Setting (Bertrand, Ghorpade and Rubin).** Let $b \in \mathbb{N}$ be a jump bound. A *round-based process template* is a tuple $\mathcal{T} = \langle \mathsf{P}, \mathsf{rc}, \mathcal{L}, \mathcal{I}, \mathcal{M}, \mathsf{Bcast}, \mathsf{Rules} \rangle$ with a finite set $\mathsf{P}$ of parameters containing the number $n$ of processes, a resilience condition $\mathsf{rc}$ (a linear arithmetic formula over $\mathsf{P}$), a finite set $\mathcal{L}$ of locations with initial locations $\mathcal{I} \subseteq \mathcal{L}$, a finite set $\mathcal{M}$ of message types, a broadcast function $\mathsf{Bcast} : \mathcal{L} \to \mathcal{M} \cup \{\bot\}$, and a finite set of rules, each with a source and a target location, a type in $\{0, \dots, b\}$ (the number of rounds it advances) and a guard (a linear arithmetic formula over $\mathcal{M} \cup \mathsf{P}$, read on numbers of received messages). The type-$0$ rules form an acyclic graph, no type-$0$ rule enters an initial location, and a monotonicity condition holds for guards met later in the same round.

For a valuation $\nu : \mathsf{P} \to \mathbb{N}$ satisfying $\mathsf{rc}$, the transition system $\mathsf{RDTS}(\mathcal{T}, \nu)$ runs $\nu(n)$ copies of $\mathcal{T}$. A configuration records, for each process, its location, its round and how many messages of each type and round tag it has received, together with how many messages of each type and round tag have been broadcast. Initially all processes are in initial locations at round $0$ and no message exists. A process may receive one more message of a given type and tag if fewer have been received than broadcast; it may take a rule from its location at round $r$ if its messages tagged $r$ satisfy the guard, moving to the target location at round $r$ plus the rule's type and broadcasting $\mathsf{Bcast}$ of the target with that round tag (nothing if it is $\bot$). The *history state-count trace* of an execution maps each location $\ell$ and round $r$ to the number of rule applications entering $\ell$ at round $r$.

Formulas of *HSCL* are Boolean combinations (with $\neg$, $\wedge$) of round-local atoms $\forall r.\, \sum_{\ell} c_\ell\, \kappa(\ell, r) \le t$ and cumulative atoms $\sum_{\ell} c_\ell \sum_{r \in \mathbb{N}} \kappa(\ell, r) \le t$, with weights $c_\ell \in \mathbb{N}$ and thresholds $t = b_0 + \sum_{y} b_y y$ linear over parameters with integer coefficients; $\kappa(\ell, r)$ is read as the value of the trace at $(\ell, r)$. The *parameterized system* satisfies $\varphi$, written $\mathsf{PRDTS}(\mathcal{T}) \models \varphi$, if for every valuation $\nu$ satisfying $\mathsf{rc}$, the trace of every execution of $\mathsf{RDTS}(\mathcal{T}, \nu)$ satisfies $\varphi$ with thresholds evaluated under $\nu$. *Parameterized HSCL-verification* asks, given $\mathcal{T}$ and an HSCL formula $\varphi$, whether $\mathsf{PRDTS}(\mathcal{T}) \models \varphi$.

**Theorem (Bertrand, Ghorpade and Rubin).** Parameterized HSCL-verification is undecidable.

In the proof the template has jump bound $b = 1$. For a fixed parameter valuation, HSCL-verification reduces to LTL model checking of a finite-state system and is decidable; the parameterized problem reduces soundly and completely to LTL model checking of finite-counter systems, which is undecidable in general.

## Expansion

The reduction is from the non-halting problem for two-counter machines, extending an undecidability result for synchronous round-based algorithms to the asynchronous setting. From a machine $\mathcal{C}$ one builds a template $\mathcal{T}_{\mathcal{C}}$ in which the $r$-th configuration $(s, v_1, v_2)$ is represented at round $r$ by one controller process in a location $l_s$, $v_i$ processes in a location $l_{c_i}$ and the remaining processes in a reserve location. The controller announces a command by a broadcast, a reserve or counter process answers through an intermediate location and an acknowledgment, and everyone moves to the next round, where non-controller processes broadcast ready messages whose counts (guards such as "the ready messages number $n - 1$" and, for zero tests, "no ready message from $l_{c_i}$") let the controller check enabledness. Because several processes may react to one broadcast, the formula $\varphi_{\mathcal{C}} = \neg(\varphi_{\mathsf{ctrl}} \wedge \varphi_{\mathsf{step}} \wedge \varphi_{\mathsf{halt}})$ excludes ill-formed simulations: $\varphi_{\mathsf{ctrl}}$ allows at most one visit to controller locations per round, $\varphi_{\mathsf{step}}$ at most one increment or decrement move per round, and $\varphi_{\mathsf{halt}}$ asks that the halting location be visited. Then $\mathcal{C}$ has no halting execution if and only if $\mathsf{PRDTS}(\mathcal{T}_{\mathcal{C}}) \models \varphi_{\mathcal{C}}$.
