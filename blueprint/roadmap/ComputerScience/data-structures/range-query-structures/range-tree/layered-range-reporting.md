# Layered Range Reporting

For $d\geq 2$, consider $n$ input occurrences with coordinates in a linearly ordered set, and a box given by $d$ closed intervals in coordinate order. Put $B=10(1+\lceil\log_2 n\rceil)$, with height zero at $n=0$ and $n=1$.

**Theorem.** The static layered range tree reports a permutation of exactly the input occurrences in the box. If it reports $k$ occurrences, it uses at most $nB^{d-1}$ occupied cells and $B^{d-1}+k$ charged work. In the plane the work is $O(1+\log n+k)$. Equal-coordinate entries and coincident input occurrences are retained, including on the box boundary; a reversed interval gives no results.

Above the final two coordinates, use the same balanced positional split and attached indexes as for [ordinary range reporting](orthogonal-range-reporting-with-range-trees.md). In the final pair, tag each occurrence by its position in the penultimate-coordinate order. Each node stores its occurrences in last-coordinate order. The child catalog is the subsequence of its parent's catalog with tags in the child's positional interval; in particular, tied last-coordinate keys retain the same order in both catalogs.

Find the `< lower` and `≤ upper` last-coordinate ranks by binary search at the root of this final pair. For a parent gap $j$, the child position table stores the number of child occurrences in the first $j$ parent entries. This is exactly the child's rank for either query boundary: the predicate selecting entries before the boundary holds on a prefix of the parent, and filtering to the child retains exactly the child entries from that prefix. This includes gap zero and the gap after the last item. Thus each boundary takes one indexed read to transfer to a child; no binary search of a child catalog is needed. At each selected canonical node, read the positions between those boundaries in descending order, prepending each reference once to the shared output tail. Composition applies the right continuation once and the left continuation once, preserving the canonical-node output order without copying child lists or materializing a slice.

The final pair uses only the two root searches and a constant number of indexed position reads per inspected node, instead of another logarithmic search per canonical node. At each depth of the penultimate position tree, total catalog length is at most $n$, and each nonempty node's storage for its catalog and position tables is linear in its length. Counting these depths gives the space bound for the final pair. Each earlier coordinate contributes at most one further logarithmic factor to both search and storage. The fixed visit charge includes child-table accesses, continuation construction and application, and setup and exit operations; the emission charge includes one catalog read, a tag projection, the loop and count operations, and one cons. The stored output count is proved equal to output length, with no recounting pass. Static storage excludes point payloads, the coordinate oracle, and transient query workspace. The model assumes unit-cost coordinate access and comparison and does not bound preprocessing, bit complexity or evaluator time.
