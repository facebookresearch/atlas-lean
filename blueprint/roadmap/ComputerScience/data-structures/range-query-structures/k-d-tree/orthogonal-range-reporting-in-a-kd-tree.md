# Orthogonal range reporting in a kd-tree

Let $P$ be a list of $n$ planar points over a linearly ordered coordinate type. Assume that no two entries share an x coordinate or a y coordinate. The [kd-tree](kd-tree.md) stores one point per leaf. Its root splits on x, its children on y, and the axes alternate thereafter. A node of size $m\ge 2$ has $\lfloor m/2\rfloor$ points on the left and the remainder on the right; a singleton is a leaf and the empty input gives the empty tree.

**Theorem.** There is a constant $C>0$, independent of the points, coordinate type and query, with the following properties. Preprocessing $P$ produces a valid median-shaped rank tree. The number of stored tree constructors plus dictionary entries is at most $C(n+1)$, and preprocessing work is at most $C(n+1)(1+\lceil\log_2 n\rceil)$, taking the ceiling log at zero to be zero. For any corners $l,u$, the answer is a permutation of the entries $p$ of $P$ satisfying $l_x\le p_x\le u_x$ and $l_y\le p_y\le u_y$. If the answer has length $k$, query work is at most $C(1+\lfloor\sqrt n\rfloor+k)$. This includes point and line queries; a reversed interval has empty output. Costs are in the comparison model, with constant-cost coordinate comparisons, operations on word-sized ranks, and indexed accesses.

**Construction.** Sort once by x, attach x ranks, sort the tagged records by y and attach y ranks. Indexed writes recover the x order of the rank pairs. At each split, divide the current order by position, stably partition the opposite order, and interchange the roles of the two orders. These passes cost linear work per level; they do not sort recursively. The stored index includes both dictionaries: the original points in x order and the coordinates in y order. Each entry and each tree constructor has constant size in words or references.

**Closed boxes and split ownership.** At a median coordinate $s$, the left point set has coordinate $<s$ and the right one has coordinate $\ge s$. A lower-bound search counts keys strictly below the lower endpoint; an upper-bound search counts keys at most the upper endpoint. If those counts are $i,j$, the query selects precisely ranks $i,\dots,j-1$, including when an endpoint is a stored key. The searches use the same dictionaries for every query. In integer rank space the keys are even, and the separator immediately before rank $t$ is $2t-1$. The [split-coordinate reporter](report-aux.md) therefore never compares equal query and split coordinates. For a line query at $s$, only the right child is entered at that split. Each rank hit takes one indexed lookup to return its original point.

**Why the query is output-sensitive.** The reporter tests splits rather than classifying whole rectangles. Inside a contained subtree it continues through every constructor: $b$ leaves account for $2b-1$ visits, not one. Maximal contained subtrees are disjoint, so their total cost is $O(k)$. A remaining visited cell meets a side of the rank box. A supporting line can enter both children on a perpendicular split, but at most one on a parallel split, by the boundary convention. Thus at most two grandchildren per cell can meet that line. Summing over the levels of a median tree of height at most $\lceil\log_2 n\rceil$ gives $O(\sqrt n)$ boundary visits for $n\ge 1$. The four initial binary searches cost $O(1+\log(n+1))$, absorbed by the query bound.
