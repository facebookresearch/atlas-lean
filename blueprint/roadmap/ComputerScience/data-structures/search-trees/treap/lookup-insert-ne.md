# Treap insertion does not change the lookup of other keys

Let the keys come from a linearly ordered type and let $t$ be a treap tree that is ordered by key (at every node each key of the left subtree is less than the node's key and the node's key is less than each key of the right subtree); no heap condition on priorities is assumed. For all keys $q \ne k$, every value $v$ and every priority $p \in \mathbb{N}$, looking up $q$ in the tree obtained from $t$ by inserting key $k$ with value $v$ and priority $p$ (split the tree at $k$, drop any entry stored at $k$, merge the part below $k$ with the single node $(k, v, p)$, then merge the result with the part above $k$, all merges guided by priority) returns the same optional value as looking up $q$ in $t$. Lookup follows the search-tree comparisons and returns the value stored with the key, or nothing.
