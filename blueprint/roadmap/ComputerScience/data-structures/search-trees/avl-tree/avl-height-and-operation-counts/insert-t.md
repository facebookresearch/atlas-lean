# Counted AVL insertion

Let the keys be linearly ordered and let $x$ be a key. Counted insertion of $x$ returns a tree together with a natural-number cost. Into the empty tree it returns the node with key $x$, two empty subtrees and cached height $1$, at cost $1$ (one node rebuild). At a node $t$ with key $k$, left subtree $L$ and right subtree $R$, it charges $1$ for visiting the node and $1$ for the comparison $x < k$. If $x < k$, counted insertion of $x$ into $L$ yields $L'$ and the result is counted rebalancing of $L'$, $k$, $R$. Otherwise it charges $1$ more for the comparison $k < x$; if $k < x$, counted insertion into $R$ yields $R'$ and the result is counted rebalancing of $L$, $k$, $R'$; otherwise ($x = k$) it returns $t$ unchanged, at total cost $3$ for this node. The costs of the recursive call and of the rebalancing are added.

In this operation-count model one unit is charged for each visit to a nonempty node in a recursive traversal, each executed key comparison ($<$), each inspection of a nonempty heavy child or inner grandchild during rebalancing, and each node rebuild; reading and comparing cached heights, arithmetic on them, pattern matching, recursive calls themselves and returning existing subtrees cost nothing. The count is not CPU time or Turing-machine time.
