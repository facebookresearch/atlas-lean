# Counted AVL deletion

Let the keys be linearly ordered and let $x$ be a key. Counted deletion of $x$ returns a tree together with a natural-number cost. On the empty tree it returns the empty tree at cost $0$. At a node with key $k$, left subtree $L$ and right subtree $R$, it charges $1$ for visiting the node and $1$ for the comparison $x < k$. If $x < k$, counted deletion of $x$ from $L$ yields $L'$ and the result is counted rebalancing of $L'$, $k$, $R$. Otherwise it charges $1$ more for the comparison $k < x$; if $k < x$ it proceeds symmetrically in $R$. Otherwise ($x = k$) it returns $R$ if $L$ is empty and $L$ if $R$ is empty, with no further cost; if both are nonempty, counted leftmost-key search in $R$ with default $k$ yields $m$, counted removal of the leftmost key of $R$ yields $R''$, and the result is counted rebalancing of $L$, $m$, $R''$. All costs are added, so the two traversals of $R$ are charged separately.

In this operation-count model one unit is charged for each visit to a nonempty node in a recursive traversal, each executed key comparison ($<$), each inspection of a nonempty heavy child or inner grandchild during rebalancing, and each node rebuild; reading and comparing cached heights, arithmetic on them, pattern matching, recursive calls themselves and returning existing subtrees cost nothing. The count is not CPU time or Turing-machine time.
