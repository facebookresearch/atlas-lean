# Steensgaard's unification constraints

For programs with the normalized pointer operations and abstract cells of [Andersen's inclusion constraints](andersen-s-inclusion-constraints.md), Steensgaard's analysis uses a term variable $[\![c]\!]$ for each abstract cell $c$ and a unary term constructor $\uparrow$, where $\uparrow t$ stands for a pointer to $t$; terms are *regular*, possibly cyclic, terms, so that an equation such as $[\![p]\!] = {\uparrow}[\![p]\!]$, generated by $p = \&p$, has a solution. It generates the equations

- $X = \mathtt{alloc}\ P$ at site $i$: $[\![X]\!] = {\uparrow}[\![\mathtt{alloc}\text{-}i]\!]$;
- $X_1 = \&X_2$: $[\![X_1]\!] = {\uparrow}[\![X_2]\!]$;
- $X_1 = X_2$: $[\![X_1]\!] = [\![X_2]\!]$;
- $X_1 = {*}X_2$: $[\![X_2]\!] = {\uparrow}\alpha$ and $[\![X_1]\!] = \alpha$ for a fresh term variable $\alpha$;
- ${*}X_1 = X_2$: $[\![X_1]\!] = {\uparrow}\alpha$ and $[\![X_2]\!] = \alpha$ for a fresh term variable $\alpha$;
- $X = \mathtt{null}$: no equation;

at most two per operation, and solves them by unification under the injectivity axiom ${\uparrow}\alpha_1 = {\uparrow}\alpha_2 \implies \alpha_1 = \alpha_2$. Unification of regular terms never fails, since $\uparrow$ is the only constructor. The points-to sets are

$$\mathrm{pt}(p) = \{t \in \mathrm{Cell} \mid [\![p]\!] = {\uparrow}[\![t]\!]\}$$

in the most general unifier. Assignments are thus treated as bidirectional: after $X_1 = X_2$ the two variables have the same points-to set.
