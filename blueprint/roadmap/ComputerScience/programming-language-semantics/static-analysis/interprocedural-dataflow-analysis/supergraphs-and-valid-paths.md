# Supergraphs and valid paths

A *supergraph* $G^* = (N^*, E^*)$ represents a program as a collection of flow graphs $G_1, G_2, \dots$, one for each procedure, one of which, $G_{\mathrm{main}}$, represents the main procedure. Each flow graph $G_p$ has a unique start node $s_p$ and a unique exit node $e_p$. A call is represented by a *call node* $c$ and a *return-site node* $r$, and besides the ordinary intraprocedural edges each call contributes three edges:
- an intraprocedural *call-to-return-site* edge $c \to r$;
- an interprocedural *call-to-start* edge from $c$ to the start node of the called procedure;
- an interprocedural *exit-to-return-site* edge from the exit node of the called procedure to $r$.

Give each call node a unique index $i$, label its call-to-start edge with an opening parenthesis $(_i$ and the corresponding exit-to-return-site edge with $)_i$, and leave the other edges unlabelled.
- A path between two nodes of one procedure is *same-level valid* if its sequence of labels is generated by $\mathit{matched} \to (_i\ \mathit{matched}\ )_i\ \mathit{matched} \mid \varepsilon$.
- A path is *valid* if its sequence of labels is generated by $\mathit{valid} \to \mathit{valid}\ (_i\ \mathit{matched} \mid \mathit{matched}$.

$\mathrm{IVP}(m, n)$ denotes the set of valid paths from $m$ to $n$. Valid paths from $s_{\mathrm{main}}$ respect the call stack: every return goes back to the site of the call it returns from, although some calls may not have returned yet.
