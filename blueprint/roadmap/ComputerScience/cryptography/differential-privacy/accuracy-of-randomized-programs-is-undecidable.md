# Accuracy of randomized programs is undecidable

Whether a randomized program, such as a differential privacy mechanism, meets a given accuracy specification relative to the deterministic function it approximates is undecidable, both at a given input and at all inputs.

**Accuracy.** Let $P$ be a randomized program with inputs $\mathcal{U}$ and outputs $\mathcal{V}$, measured against a deterministic program $\det(P)$, with an input distance $d : \mathcal{U} \times \mathcal{U} \to \mathbb{R} \cup \{\infty\}$, required only to satisfy $d(u, u') = d(u', u) \ge 0$ and $d(u, u) = 0$ (not a metric in general; Section 2), and, for each input $u$, an output distance $d'_u$ on $\mathcal{V}$. The *disagreement distance* of $P$ at $u$ is $\mathrm{dd}(P, u) = d(u, \mathcal{U} \setminus \det(P)^{-1}(\det(P)(u)))$, the distance from $u$ to the nearest input on which $\det(P)$ gives another output. Write $B(v, u, \gamma) = \{v' \in \mathcal{V} : d'_u(v, v') \leq \gamma\}$. For $\alpha, \gamma \geq 0$ and $\beta \in [0,1]$, $P$ is *$(\alpha, \beta, \gamma)$-accurate at $u$* if $\mathrm{dd}(P, u) > \alpha$ implies

$$
\Pr\big(P(u) \in B(\det(P)(u), u, \gamma)\big) \geq 1 - \beta .
$$

For a program $P_\epsilon$ depending on a privacy budget $\epsilon$ in an interval $I$, and an admissible region $\mathrm{reg}(\epsilon, u)$ of triples $(\alpha, \beta, \gamma)$:

- *Accuracy-at-an-input*: given $u$, is $P_\epsilon$ $(\alpha, \beta, \gamma)$-accurate at $u$ for all $\epsilon \in I$ and all $(\alpha, \beta, \gamma) \in \mathrm{reg}(\epsilon, u)$?
- *Accuracy-at-all-inputs*: does this hold for every input $u$?

**Theorem (Barthe, Chadha, Krogmeier, Sistla and Viswanathan).** Both Accuracy-at-an-input and Accuracy-at-all-inputs are undecidable for the general class of randomized programs (Theorem 8). In the finite-input form given by the corrected proof (`## Expansion`), instances are *counter programs*: finite texts generated by the grammar below, read as [fully probabilistic programs](../../program-logics-and-verification/expected-run-time-calculus/probabilistic-programs-with-a-run-time-model.md). A counter program uses finitely many variables ranging over $\mathbb N$, among them $\mathit{in}$ and $\mathit{out}$, with natural-number literals $n$:

$$
\begin{aligned}
e &::= n \mid x \mid x + 1 \mid x \mathbin{\dot-} 1, \\
b &::= x = n \mid \neg b \mid b \wedge b, \\
c &::= \mathtt{skip} \mid x := e \mid x := \mathtt{coin} \mid c ; c \mid \mathtt{if}\ b\ \mathtt{then}\ c\ \mathtt{else}\ c \mid \mathtt{while}\ b\ \mathtt{do}\ c,
\end{aligned}
$$

where $x \mathbin{\dot-} 1 = \max(x - 1, 0)$. An assignment $x := e$ and every guard $b$ are deterministic (Dirac) expressions, and $x := \mathtt{coin}$ is the only random assignment: it sets $x$ to $0$ or $1$ with probability $1/2$ each. On input $u \in \{0, 1\}$ the program starts with $\mathit{in} = u$ and every other variable $0$, and runs on its [operational Markov decision process](../../program-logics-and-verification/expected-run-time-calculus/operational-markov-decision-process-of-a-probabilistic-program.md), which has no nondeterminism here. The output is the value of $\mathit{out}$ at termination: $\Pr(P(u) = v)$ is the probability of terminating with $\mathit{out} = v$, and non-terminating runs give no output. Inputs and outputs are in $\{0, 1\}$, $\det(P)$ is the identity on $\{0, 1\}$, both distances are discrete ($d(0, 1) = d'_u(0, 1) = 1$), $\mathrm{reg} = \{(0, 0, 0)\}$, and nothing depends on $\epsilon$. The appendix of the source describes its reduction program in prose with exactly these ingredients: five variables, two counters and a control state initialized to zero and to the initial state, steps of a two-counter machine, a probability-$1/2$ choice, and the value of $\mathit{out}$ at termination as output. For these programs:

1. it is undecidable, given $P$, whether $P$ is $(0, 0, 0)$-accurate at input $0$;
2. it is undecidable, given $P$, whether $P$ is $(0, 0, 0)$-accurate at every input. The programs of the reduction output $1$ with probability $1$ on input $1$, so they are accurate at $1$ and the two questions agree on them; on the whole class the two properties differ (a program that outputs $0$ on both inputs is accurate at $0$ but not at $1$).

The source does not fix a syntax for the general class of randomized programs, and its Theorem 8 is stated for that class; $I$ is an interval with rational end-points. By contrast, the source identifies a non-trivial class of probabilistic programs for which accuracy is decidable, unconditionally or assuming Schanuel's conjecture (Section 6).

## Expansion

Given a two-counter machine $M$ with control states numbered $0, \dots, m$ ($0$ initial), build a counter program $P$ with variables $\mathit{in}$, $\mathit{out}$, $\mathit{c}_1$, $\mathit{c}_2$, $\mathit{state}$ and two auxiliary variables $\mathit{run}$ and $r$. On input $1$ it sets $\mathit{out} := 1$ and stops. On input $0$ it sets $\mathit{run} := 1$ and executes $\mathtt{while}\ \mathit{run} = 1\ \mathtt{do}\ \dots$: if $\mathit{state}$ equals the final state, set $\mathit{out} := 1$ and $\mathit{run} := 0$; otherwise set $r := \mathtt{coin}$, and if $r = 0$ set $\mathit{run} := 0$ (so $\mathit{out}$ stays $0$), else simulate one step of $M$ by a case distinction on $\mathit{state} = q$ with tests $c_j = 0$, updates $c_j := c_j + 1$ and $c_j := c_j \mathbin{\dot-} 1$, and an assignment of the next control state. If $M$ halts from zero counters after $k$ steps, the output on input $0$ is $1$ with probability $2^{-k} > 0$; if it never halts, the output is $0$ with probability $1$. With $\det(P)$ the identity on $\{0,1\}$, the disagreement distance at $0$ is $1 > 0$, so $P$ is $(0,0,0)$-accurate at input $0$ iff $M$ does not halt. The appendix of the source (proof of Theorem 8) lets the coin jump to the final state instead, which makes the output $1$ with probability $1$ on every machine; the stop-with-output-$0$ step is the correction that makes the reduction work.

A good expansion links a page defining the output distribution $\Pr(P(u) = v)$ of a fully probabilistic program from its operational Markov decision process (linked above), the quantity the accuracy condition is about.
