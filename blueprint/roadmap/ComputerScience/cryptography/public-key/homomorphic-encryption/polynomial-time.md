# Polynomial Time

Four fixed single-tape Turing machines must realize the actual distributions of key generation, encryption and public evaluation and the deterministic decryption result on the specified bit encodings. Encryption must work on every public key and message, evaluation on every public key and ciphertext tuple for each admitted circuit, and decryption on every secret key and ciphertext. These runtime requirements range over the declared types, not just the supports of key generation and fresh encryption. Decryption receives the security parameter, the secret key and the ciphertext, but no level. A randomized machine receives a uniform bit tape; its output distribution must agree exactly, and the step bound must hold on every tape.

This runtime model requires a finite operation type. The family index specifies either no level or a positive level $d$. Put $k=\lambda$ with no level and $k=\lambda+d$ otherwise. One pair of polynomials $q,p$ bounds the computation uniformly: the random tape has $q(k)$ bits and the machine takes at most $p(k)$ steps. Only for evaluation replace $k$ by $k+t+g$, where $t$ is the number of circuit inputs and $g$ the number of gates. With no level, every circuit is admitted; at level $d$, circuits of depth at most $d$ are admitted.

The machine reads the actual [circuit description](circuit-code.md), including each encoded gate name and each incoming wire. On a fixed finite basis with fixed operation codes, gate-name lengths and fan-ins are bounded by constants. A predecessor index is less than $t+g$, so even its unary representation uses at most $t+g+1$ bits before its wire tag. Thus the description length grows at most polynomially in $t+g$. No such bound on gate names or fan-ins follows for an arbitrary signature. Gentry's Definition 2.1.5 specifies a gate set without requiring finiteness; Theorem 4.2.2 uses the number of wires as its size parameter. The input-plus-gate budget here is a finite-basis convention, not a definition of wire count.
