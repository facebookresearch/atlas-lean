# Slack and the critical path of a project network

Let a project be an activity-on-arc network: a set of events (vertices) and a finite set of activities (arcs), each arc $e$ running from its tail event to its head event, with a duration $d(e)$. Parallel arcs are allowed. The durations are taken in $\mathbb{R}$ or, more generally, in any linearly ordered additive commutative group; in a project they are nonnegative, and only the comparison with the source's linear program below needs that. A walk from $u$ to $v$ is a sequence of arcs, each starting where the previous one ends, the first starting at $u$ and the last ending at $v$ (the empty walk when $v = u$), and its length is the sum of its durations. The network is acyclic: its only closed walk is the empty one, so no walk visits an event twice and walks are paths. It has a source $s$ and a sink $t$ such that every event lies on some $s$–$t$ path, that is, some path runs from $s$ to it and some path from it to $t$; the statement assumes this and says nothing about networks with an event off every $s$–$t$ path. With $\ell(u, v)$ the length of a longest $u$–$v$ path, which exists whenever some path runs from $u$ to $v$, put $L = \ell(s, t)$.

$L$ is the minimum project duration with unlimited resources, in the following model: an event schedule assigns each event $v$ a time $\tau(v)$ such that every activity fits between its events, $\tau(u) + d(e) \le \tau(v)$ for each arc $e$ from $u$ to $v$, its project duration is $\tau(t) - \tau(s)$, and $L$ is the least project duration of an event schedule. If every duration is nonnegative, every event of an event schedule lies between $\tau(s)$ and $\tau(t)$, and $L$ is also the least $\tau(t)$ over event schedules with $\tau(s) = 0$ and $\tau(v) \ge 0$ for every event $v$, so that no event precedes the start, as in the source's linear program. For durations of any sign the statement is about the event-schedule model, which lets events precede $\tau(s)$.

For an event $v$ put $ES(v) = \ell(s, v)$ and $LS(v) = L - \ell(v, t)$; then $LS(v) - ES(v) \ge 0$, with equality exactly when $v$ lies on a longest $s$–$t$ path, that is, when some path of length $L$ from $s$ to $t$ is a path from $s$ to $v$ followed by a path from $v$ to $t$. For an arc $e$ from $u$ to $v$ the total float $TF(e) = LS(v) - ES(u) - d(e)$ satisfies $TF(e) \ge 0$, with equality exactly when $e$ is an arc of a longest $s$–$t$ path.

## Sources

- J. E. Beasley, *OR-Notes: Network analysis — activity on arc examples*, <https://www.brunel.ac.uk/~mastjjb/jeb/or/netmore.html>. Its worked examples, starting with "Network analysis example 1990 UG exam", compute the earliest start times $E_i$ of the events by a forward pass, the latest start times $L_j$ by a backward pass and the float $F_{ij} = L_j - E_i - T_{ij}$ of each activity, note that every float is nonnegative, and identify the activities of float zero as those forming the critical path; "Network analysis example 1988 UG exam" also writes the minimum overall project completion time as a linear program over event times, with the start event at time $0$ and no event time negative. The source works examples; the general statements are derived on this page.
