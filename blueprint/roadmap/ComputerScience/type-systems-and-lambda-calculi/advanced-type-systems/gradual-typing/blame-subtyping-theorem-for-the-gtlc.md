# The blame-subtyping theorem for the GTLC

On the types of the [gradually typed λ-calculus](the-gradually-typed-lambda-calculus.md), let $<:$ be generated by $B <: B$, $? <: ?$, $T <: ?$ when $T <: G$ for a ground
type $G$, and $T_1 \to T_2 <: S_1 \to S_2$ when $S_1 <: T_1$ and $T_2 <: S_2$. Suppose $\emptyset \vdash e \rightsquigarrow f : T$ by [cast insertion](cast-calculus-and-cast-insertion.md),
and every cast $f' : T_1 \Rightarrow^\ell T_2$ in $f$ that carries the label $\ell$ satisfies $T_1 <: T_2$. Then $e$ does not evaluate to $\mathrm{blame}_{T'}\, \ell$ for any $T'$.
So fully static regions of a gradually typed program are never to blame.

The hypothesis must cover every cast with the label, not one of them: cast insertion gives the function cast and the argument cast of an application the
same label. In $((\lambda x{:}?.\, x)\, \mathrm{true})\, 0$, the outer application inserts the cast $0 : \mathrm{int} \Rightarrow^\ell ?$, with $\mathrm{int} <: ?$, and the projection
$(\cdot) : ? \Rightarrow^\ell ? \to ?$; the function position evaluates to the injected Boolean $\mathrm{true} : \mathrm{bool} \Rightarrow ?$, and the projection then reduces to
$\mathrm{blame}_{? \to ?}\, \ell$. The source states the theorem for a single cast with $T_1 <: T_2$, which this example refutes.
