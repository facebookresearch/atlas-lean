# Splitting a preorder at roots

The vertex type has a Boolean equality test and a hash function, used to store finite sets of vertices in hash sets; the Boolean test need not agree with equality. Splitting a preorder at a hash set of roots walks the preorder with an accumulator that holds the pending block in reverse order: at a vertex $v$, when the hash-set lookup of $v$ returns true and the pending block is nonempty, the pending block is emitted reversed and a new pending block $[v]$ starts; otherwise $v$ is put at the front of the pending block; at the end of the preorder a nonempty pending block is emitted reversed (so remaining input $[\,]$ with pending block $[a, b]$ gives $[[b, a]]$). Each emitted block therefore lists its vertices in the order of the preorder. In a depth-first preorder the vertices of each tree are contiguous and each tree starts at its root, so when the lookup returns true exactly on the roots of the forest, splitting recovers the trees. Without that, it need not: for two isolated roots $a$, $b$ and a Boolean test that always returns false, the lookups fail and the split of $[a, b]$ is the single block $[a, b]$.
