# Splitting a depth-first preorder into its trees

The vertex type has a Boolean equality test that agrees with equality and a hash function, so finite sets of vertices can be stored in hash sets. Splitting a preorder at a hash set of roots walks the preorder with an accumulator that holds the pending block in reverse order: at a vertex $v$, when the hash-set lookup of $v$ returns true and the pending block is nonempty, the pending block is emitted reversed and a new pending block $[v]$ starts; otherwise $v$ is put at the front of the pending block; at the end of the preorder a nonempty pending block is emitted reversed (so remaining input $[\,]$ with pending block $[a, b]$ gives $[[b, a]]$). Each emitted block therefore lists its vertices in the order of the preorder. The split of a preorder at a list of roots stores the roots in a hash set and runs this walk from an empty pending block. Since the Boolean test agrees with equality, the lookup returns true exactly on the listed roots. In a depth-first preorder the vertices of one tree are contiguous and each tree starts with its root, so splitting at the forest roots recovers the trees.
